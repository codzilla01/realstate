# المكتب العقاري · Al Maktab

واجهة عربية للعقارات ولوحة إدارة متصلة بها. يدعم المشروع التشغيل المحلي بـ SQLite، والنشر على Vercel بقاعدة Turso خارجية. يرسل الخادم رموز تسجيل الدخول عبر Resend أو SMTP.

## النشر على Vercel

1. استورد المستودع من Git إلى Vercel. اختر **Other** إن طُلب منك اختيار إطار، واترك المجلد الجذري للمستودع. يضبط `vercel.json` أمر `npm run build` ومخرجات `dist` ومساري `/admin` و`/api/*`. لا تستخدم إعداد نشر الملفات الثابتة فقط.
2. أنشئ قاعدة بيانات على [Turso](https://turso.tech/) ورمز وصول يسمح بالكتابة. أضف المتغيرات التالية من **Settings → Environment Variables** داخل مشروع Vercel، ثم أعد النشر بعد إضافتها:

   | المتغير | الغرض |
   | --- | --- |
   | `TURSO_DATABASE_URL` | رابط قاعدة Turso الخاص بمشروعك (`libsql://…`) |
   | `TURSO_AUTH_TOKEN` | رمز الوصول للقراءة والكتابة، على الخادم فقط |
   | `ADMIN_EMAIL` | صندوق البريد المصرّح له بدخول لوحة الإدارة |
   | `AUTH_SECRET` | قيمة عشوائية مستقلة لتأمين رموز الدخول عبر مثيلات Vercel؛ ولّدها بالأمر أدناه |
   | `RESEND_API_KEY` | مفتاح إرسال Resend، موصى به على Vercel لأنه يستخدم HTTPS |
   | `MAIL_FROM` | عنوان مرسل من نطاق معتمد في Resend |
   | `SEED_DEMO` | اختياري: `true` لإضافة عقارات نموذجية عند بدء قاعدة جديدة؛ اتركه `false` للبيانات الفعلية |

   ```sh
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

3. بعد النشر، افتح `/api/site` للتأكد من أن استجابة قاعدة البيانات JSON، ثم افتح `/admin` في تبويب مستقل واطلب رمز الدخول. إذا ظهرت قاعدة البيانات غير متاحة، راجع المتغيرين `TURSO_DATABASE_URL` و`TURSO_AUTH_TOKEN` وسجل الوظيفة في Vercel. لا تحتاج إلى تشغيل `npm start` على Vercel.

يتولى الخادم إنشاء الجداول تلقائيًا عند أول استدعاء. لا يُستخدم قرص Vercel لتخزين العقارات أو الطلبات أو الجلسات أو رموز التحقق. قاعدة Turso الجديدة لا تستورد تلقائيًا أي سجلات من SQLite المحلي؛ خذ نسخة احتياطية ورتّب ترحيل البيانات قبل التحويل إذا كانت لديك سجلات فعلية. افصل قواعد بيانات **Preview** و**Production** ومتغيرات الدخول بينهما. احتفظ بالمفاتيح في إعدادات البيئة فقط، ولا تضف بادئة عامة مثل `NEXT_PUBLIC_`. عند تغيير البريد أو `AUTH_SECRET`، لا تعمل الجلسات القديمة على النشر الجديد؛ احمِ روابط النشرات السابقة أو احذفها إذا لم تعد مطلوبة.


## التشغيل

يتطلب **Node.js 22** (الإصدار 22.13 على الأقل).

```sh
npm ci
cp .env.example .env
# لتفعيل دخول الإدارة، أدخل ADMIN_EMAIL وإعدادات Resend أو SMTP داخل .env.
npm start
npm test
```

- `/` موقع الزوار: البحث، تصفية العقارات وترتيبها، المحفوظات المحلية، روابط العقارات، وطلبات المعاينة أو الاستشارة.
- `/admin` لوحة الإدارة: المسودات والمعاينة الخاصة والنشر، إدارة التوفر والعقارات المميزة، متابعة الطلبات والمواعيد، تصدير النتائج، وتحرير محتوى الواجهة.
## تفعيل الدخول بالبريد

1. عيّن `ADMIN_EMAIL` إلى البريد الوحيد المخوّل بإدارة الموقع. استخدم صندوق بريد خاصًا بالإدارة ومحمياً بالمصادقة متعددة العوامل.
2. اضبط `RESEND_API_KEY` و`MAIL_FROM` لاستخدام Resend. ولخادم SMTP بدلًا منه، عيّن `SMTP_HOST` و`SMTP_PORT` و`SMTP_FROM` حسب مزود الإرسال. إذا تطلّب المصادقة، اضبط `SMTP_USER` و`SMTP_PASSWORD` معًا في بيئة الخادم. المنفذ `587` يتطلب STARTTLS، والمنفذ `465` يستخدم TLS من بداية الاتصال. استخدم عنوان إرسال معتمدًا لدى المزود.
3. أعد تشغيل الخادم، وافتح `/admin` في المتصفح مباشرة، وأدخل البريد ثم الرمز المرسل إليه. الرمز صالح لخمس دقائق، ويُستخدم مرة واحدة في المتصفح الذي طلبه. بعد خمس محاولات خاطئة يلزم طلب رمز جديد. يمكن إعادة الطلب بعد دقيقة، وقد تطول المهلة عند تكرار الطلبات. إذا لم يصل البريد، راجع الرسائل غير المرغوب فيها وسجل مزود الإرسال.

لا توجد كلمة مرور احتياطية. إذا لم تكتمل إعدادات البريد، يظل الموقع العام متاحًا ويعرض `/admin` أن الدخول غير مفعّل. تظهر أسباب تعطل اتصال البريد في سجل الخادم دون طباعة كلمات المرور أو الرموز. عند الترقية من النسخة القديمة احذف `ADMIN_PASSWORD`، وسيحتاج المشرف إلى تسجيل الدخول مرة أخرى. تغيير البريد الإداري يلغي الجلسات السابقة أيضًا. الاختبارات تستخدم مرسلًا محليًا بديلًا؛ للتحقق من مزود البريد الفعلي، شغّل الأمر التالي **من بيئة الاستضافة** بعد ضبط المتغيرات:

```sh
npm run admin:check-email
```

يرسل الأمر رسالة اختبار بلا رمز دخول إلى البريد الإداري، أو يبيّن سبب الفشل. إذا قبلتها خدمة البريد ولم تصل، تحقّق من مجلد الرسائل غير المرغوب فيها وسجل التسليم عند المزود. إذا وصل رمز الدخول لكن لم تقبله المعاينة، افتح `/admin` في تبويب مستقل واطلب رمزًا من نفس التبويب.

## البيانات والنشر

- الموقع يحتاج إلى استضافة تدعم Node.js؛ استضافة الملفات الثابتة وحدها لا تشغّل خدمات العقارات والطلبات.
- شغّل بالخيار `NODE_ENV=production` خلف وكيل HTTPS يحافظ على ترويسة `Host`. يجب إعداد البريد والإرسال لتفعيل الدخول، ويصبح ملف تعريف ارتباط الإدارة `Secure` تلقائيًا.
- في التشغيل المحلي تُحفظ البيانات في SQLite. إذا لم تضبط `AUTH_SECRET` محليًا، اطلب رمزًا جديدًا بعد إعادة تشغيل الخادم؛ على Vercel المفتاح الثابت مطلوب ليُتحقق من الرمز عبر مثيلات مختلفة.
- `DATABASE_PATH` يحدّد مسار قاعدة البيانات؛ المسار الافتراضي `data/almaktab.sqlite`. اربط المسار بوحدة تخزين دائمة واحتفظ بنسخ احتياطية آمنة باستخدام أدوات النسخ الاحتياطي لـ SQLite. هذه القاعدة تتضمّن بيانات تواصل العملاء؛ لا تجعلها متاحة عبر الويب أو Git.
- شغّل على قاعدة جديدة مع `SEED_DEMO=false` للبيانات الحقيقية. إيقاف البذر لا يحذف العقارات النموذجية الموجودة سابقًا؛ يمكن إلغاء نشرها من اللوحة. الصور النموذجية توضيحية ومولّدة وليست توثيقًا لعقارات معروضة للبيع.
- بيانات `localStorage` الخاصة بالنسخة السابقة لا تُرحّل تلقائيًا، لأنها محفوظة في متصفح كل مستخدم. أدخل أي سجلات مطلوبة في المنظومة الجديدة بعد مراجعتها.
- تحديد موعد في اللوحة يحفظه بتوقيت الإمارات. لا تُرسل إشعارات المعاينة إلى العميل تلقائيًا؛ يمكن التواصل معه باستخدام بيانات الطلب.
- لوحة الإدارة في هذا الإصدار تدعم بريدًا إداريًا واحدًا، وليس حسابات فريق متعددة. طلبات العملاء متاحة في لوحة الإدارة ويمكن تحديث قائمتها من داخل اللوحة.
- لا تستخدم أي بيانات اعتماد كانت مضمّنة في النسخة السابقة. ألغِ رمز بوت Telegram القديم أو دوّره من الجهة المسؤولة؛ حذفه من الشفرة الحالية لا يمحوه من سجل Git.
