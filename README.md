# المكتب العقاري · Al Maktab

واجهة عربية للعقارات ولوحة إدارة متصلة بها. يدعم المشروع التشغيل المحلي بـ SQLite، والنشر على Vercel بقاعدة Turso خارجية. تسجيل دخول لوحة الإدارة باسم مستخدم وكلمة مرور، دون خدمة بريد.

## النشر على Vercel

1. استورد المستودع من Git إلى Vercel. اختر **Other** إن طُلب منك اختيار إطار، واترك المجلد الجذري للمستودع. يحدد `vercel.json` بنّاء الملفات الثابتة (`npm run build` إلى `dist`) ووظيفة Node.js للـ API صراحةً. تُخدم صفحة `/admin` كملف HTML مستقل؛ وتستخدم `/api/*` وظيفة واحدة. لا تستخدم إعداد نشر الملفات الثابتة فقط.
2. أنشئ قاعدة بيانات على [Turso](https://turso.tech/) ورمز وصول يسمح بالكتابة. أضف المتغيرات التالية من **Settings → Environment Variables** داخل مشروع Vercel، ثم أعد النشر بعد إضافتها:

   | المتغير | الغرض |
   | --- | --- |
   | `TURSO_DATABASE_URL` | رابط قاعدة Turso الخاص بمشروعك (`libsql://…`) |
   | `TURSO_AUTH_TOKEN` | رمز الوصول للقراءة والكتابة، على الخادم فقط |
   | `ADMIN_USERNAME` | اسم مستخدم الإدارة الذي تختاره |
   | `ADMIN_PASSWORD_HASH` | التجزئة التي يولّدها أمر `npm run admin:hash-password`، وليست كلمة المرور نفسها |
   | `SEED_DEMO` | اختياري: `true` لإضافة عقارات نموذجية عند بدء قاعدة جديدة؛ اتركه `false` للبيانات الفعلية |

3. بعد النشر، افتح `/api/site` للتأكد من أن استجابة قاعدة البيانات JSON، ثم افتح `/admin` في تبويب مستقل وأدخل اسم المستخدم وكلمة المرور. إذا ظهرت قاعدة البيانات غير متاحة، راجع المتغيرين `TURSO_DATABASE_URL` و`TURSO_AUTH_TOKEN` وسجل الوظيفة في Vercel. لا تحتاج إلى تشغيل `npm start` على Vercel. إذا ظهر `FUNCTION_INVOCATION_FAILED` على نشر سابق، أعد النشر من النسخة المحدّثة وتحقق أن Root Directory يشير إلى جذر المستودع. اختبر رابط الإنتاج بعد انتهاء النشر، لا الرابط الثابت للنشر السابق.

يتولى الخادم إنشاء الجداول تلقائيًا عند أول استدعاء. لا يُستخدم قرص Vercel لتخزين العقارات أو الطلبات أو الجلسات. قاعدة Turso الجديدة لا تستورد تلقائيًا أي سجلات من SQLite المحلي؛ خذ نسخة احتياطية ورتّب ترحيل البيانات قبل التحويل إذا كانت لديك سجلات فعلية. افصل قواعد بيانات **Preview** و**Production** ومتغيرات الدخول بينهما. احتفظ بالمفاتيح في إعدادات البيئة فقط، ولا تضف بادئة عامة مثل `NEXT_PUBLIC_`. عند تغيير اسم المستخدم أو تجزئة كلمة المرور، لا تعمل الجلسات القديمة على النشر الجديد؛ احمِ روابط النشرات السابقة أو احذفها إذا لم تعد مطلوبة.


## التشغيل

يتطلب **Node.js 22** (الإصدار 22.13 على الأقل).

```sh
npm ci
cp .env.example .env
# لتفعيل دخول الإدارة، اضبط ADMIN_USERNAME وADMIN_PASSWORD_HASH داخل .env.
npm start
npm test
```

- `/` موقع الزوار: البحث، تصفية العقارات وترتيبها، المحفوظات المحلية، روابط العقارات، وطلبات المعاينة أو الاستشارة.
- `/admin` لوحة الإدارة: المسودات والمعاينة الخاصة والنشر، إدارة التوفر والعقارات المميزة، متابعة الطلبات والمواعيد، تصدير النتائج، وتحرير محتوى الواجهة.
## إعداد اسم المستخدم وكلمة المرور

1. نفّذ `npm run admin:hash-password` في طرفية تفاعلية. اكتب كلمة مرور فريدة من 14 حرفًا على الأقل وأكّدها. لا يظهر ما تكتبه على الشاشة.
2. انسخ **القيمة التي تبدأ بـ `scrypt:` فقط** من الناتج إلى `ADMIN_PASSWORD_HASH`. اختر `ADMIN_USERNAME` من 3–64 حرفًا لاتينيًا أو رقمًا أو إحدى العلامات `. _ -` (اسم المستخدم غير حساس لحالة الحروف).
3. في Vercel أضف المتغيرين لبيئة **Production** ثم أعد النشر، أو ضعهما في `.env` محليًا وأعد تشغيل الخادم. في `/admin` أدخل الاسم الذي اخترته وكلمة المرور الأصلية، **وليس التجزئة**.

لا توجد بيانات دخول افتراضية. يبقى الموقع العام متاحًا إذا لم يُضبط الحساب. لم تعد متغيرات البريد القديمة (`ADMIN_EMAIL`، وإعدادات Resend وSMTP، و`AUTH_SECRET`) مطلوبة لهذا المشروع. تنتهي جلسات الدخول السابقة عند الانتقال إلى آلية الدخول الجديدة؛ لا تتغير العقارات أو الطلبات المخزنة. يُقبل حتى عشر محاولات تسجيل دخول لكل عنوان IP خلال 15 دقيقة.

## البيانات والنشر

- الموقع يحتاج إلى استضافة تدعم Node.js؛ استضافة الملفات الثابتة وحدها لا تشغّل خدمات العقارات والطلبات.
- شغّل بالخيار `NODE_ENV=production` خلف وكيل HTTPS يحافظ على ترويسة `Host`. يجب ضبط حساب الإدارة لتفعيل الدخول، ويصبح ملف تعريف ارتباط الإدارة `Secure` تلقائيًا.
- `DATABASE_PATH` يحدّد مسار قاعدة البيانات؛ المسار الافتراضي `data/almaktab.sqlite`. اربط المسار بوحدة تخزين دائمة واحتفظ بنسخ احتياطية آمنة باستخدام أدوات النسخ الاحتياطي لـ SQLite. هذه القاعدة تتضمّن بيانات تواصل العملاء؛ لا تجعلها متاحة عبر الويب أو Git.
- شغّل على قاعدة جديدة مع `SEED_DEMO=false` للبيانات الحقيقية. إيقاف البذر لا يحذف العقارات النموذجية الموجودة سابقًا؛ يمكن إلغاء نشرها من اللوحة. الصور النموذجية توضيحية ومولّدة وليست توثيقًا لعقارات معروضة للبيع.
- بيانات `localStorage` الخاصة بالنسخة السابقة لا تُرحّل تلقائيًا، لأنها محفوظة في متصفح كل مستخدم. أدخل أي سجلات مطلوبة في المنظومة الجديدة بعد مراجعتها.
- تحديد موعد في اللوحة يحفظه بتوقيت الإمارات. لا تُرسل إشعارات المعاينة إلى العميل تلقائيًا؛ يمكن التواصل معه باستخدام بيانات الطلب.
- لوحة الإدارة في هذا الإصدار تدعم حسابًا إداريًا واحدًا، وليس حسابات فريق متعددة. طلبات العملاء متاحة في لوحة الإدارة ويمكن تحديث قائمتها من داخل اللوحة.
- لا تستخدم أي بيانات اعتماد كانت مضمّنة في النسخة السابقة. ألغِ رمز بوت Telegram القديم أو دوّره من الجهة المسؤولة؛ حذفه من الشفرة الحالية لا يمحوه من سجل Git.
