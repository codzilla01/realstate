# المكتب العقاري · Al Maktab

واجهة عربية للعقارات ولوحة إدارة متصلة بها. يدعم المشروع التشغيل المحلي بـ SQLite، والنشر على Vercel بقاعدة Turso خارجية. دخول لوحة الإدارة عبر Google بالحساب المعتمد فقط، دون كلمة مرور خاصة بالموقع.

## النشر على Vercel

1. استورد المستودع من Git إلى Vercel. اختر **Other** إن طُلب منك اختيار إطار، واترك المجلد الجذري للمستودع. يحدد `vercel.json` بنّاء الملفات الثابتة (`npm run build` إلى `dist`) ووظيفة Node.js للـ API صراحةً. تُخدم صفحة `/admin` كملف HTML مستقل؛ وتستخدم `/api/*` وظيفة واحدة. لا تستخدم إعداد نشر الملفات الثابتة فقط.
2. أنشئ قاعدة بيانات على [Turso](https://turso.tech/) ورمز وصول يسمح بالكتابة. أضف المتغيرات التالية من **Settings → Environment Variables** داخل مشروع Vercel، ثم أعد النشر بعد إضافتها:

   | المتغير | الغرض |
   | --- | --- |
   | `TURSO_DATABASE_URL` | رابط قاعدة Turso الخاص بمشروعك (`libsql://…`) |
   | `TURSO_AUTH_TOKEN` | رمز الوصول للقراءة والكتابة، على الخادم فقط |
   | `ADMIN_GOOGLE_EMAIL` | بريد حساب Gmail أو Google Workspace المعتمد لإدارة الموقع |
   | `GOOGLE_OAUTH_CLIENT_ID` | معرّف تطبيق OAuth من Google Cloud |
   | `GOOGLE_OAUTH_CLIENT_SECRET` | سرّ تطبيق OAuth، على الخادم فقط |
   | `GOOGLE_OAUTH_REDIRECT_URI` | رابط عودة Google المطابق تمامًا لما سُجّل في Google Cloud؛ مثال `https://example.com/api/admin/login/google/callback` |
   | `SEED_DEMO` | اختياري: `true` لإضافة عقارات نموذجية عند بدء قاعدة جديدة؛ اتركه `false` للبيانات الفعلية |

3. بعد النشر، افتح `/api/site` للتأكد من أن استجابة قاعدة البيانات JSON، ثم افتح `/admin` في تبويب مستقل واختر **الدخول عبر Google**. إذا ظهرت قاعدة البيانات غير متاحة، راجع المتغيرين `TURSO_DATABASE_URL` و`TURSO_AUTH_TOKEN` وسجل الوظيفة في Vercel. لا تحتاج إلى تشغيل `npm start` على Vercel. إذا ظهر `FUNCTION_INVOCATION_FAILED` على نشر سابق، أعد النشر من النسخة المحدّثة وتحقق أن Root Directory يشير إلى جذر المستودع. اختبر رابط الإنتاج بعد انتهاء النشر، لا الرابط الثابت للنشر السابق.

يتولى الخادم إنشاء الجداول تلقائيًا عند أول استدعاء. لا يُستخدم قرص Vercel لتخزين العقارات أو الطلبات أو الجلسات. قاعدة Turso الجديدة لا تستورد تلقائيًا أي سجلات من SQLite المحلي؛ خذ نسخة احتياطية ورتّب ترحيل البيانات قبل التحويل إذا كانت لديك سجلات فعلية. افصل قواعد بيانات **Preview** و**Production** ومتغيرات الدخول بينهما. احتفظ بالمفاتيح في إعدادات البيئة فقط، ولا تضف بادئة عامة مثل `NEXT_PUBLIC_`. عند تغيير الحساب المعتمد أو إعدادات Google OAuth، لا تعمل الجلسات القديمة على النشر الجديد؛ احمِ روابط النشرات السابقة أو احذفها إذا لم تعد مطلوبة.


## تشخيص خطأ قاعدة البيانات على Vercel

افتح `/api/site` من **رابط الإنتاج**. إذا ظهر خطأ، يساعدك الحقل `code` في معرفة الخطوة التالية:

| الرمز | الإجراء |
| --- | --- |
| `TURSO_CONFIG_MISSING` | أضف المتغيرات المذكورة في `missing` إلى **Settings → Environment Variables → Production**؛ إذا كنت تختبر رابط معاينة، اختر **Preview** بدلًا منها. |
| `TURSO_URL_INVALID` أو `TURSO_DATABASE_NOT_FOUND` | انسخ **رابط قاعدة البيانات نفسها** من Turso، وليس رابط لوحة التحكم أو اسم القاعدة. |
| `TURSO_ACCESS_DENIED` | ولّد رمز وصول جديدًا لنفس القاعدة بصلاحية القراءة والكتابة، وتحقق أنه غير منتهي الصلاحية. |
| `TURSO_UNAVAILABLE` | راجع حالة Turso وسجل الوظيفة في Vercel، أو شغّل فحص الاتصال أدناه. |

من طرفية Turso، استخدم اسم قاعدتك بدل `<database>` في الأمرين `turso db show <database> --url` و`turso db tokens create <database>`. انسخ القيم إلى مشروع Vercel وأعد النشر بعد كل تغيير. بيانات دخول الإدارة لا تُغني عن إعداد قاعدة البيانات.

يمكنك اختبار القيم على جهازك بعد `npm ci` بوضعها في `.env` ثم تشغيل `npm run db:check`. يستخدم الفحص الاتصال نفسه الذي يستخدمه نشر Vercel، ويتأكد من تهيئة الجداول دون إضافة عقارات تجريبية. لا يطبع الرموز السرية. لا ترسل الرمز أو ملف `.env` لأي شخص.

## التشغيل

يتطلب **Node.js 22** (الإصدار 22.13 على الأقل).

```sh
npm ci
cp .env.example .env
# لتفعيل دخول الإدارة، اضبط حساب Google وتطبيق OAuth داخل .env.
npm start
npm test
```

- `/` موقع الزوار: البحث، تصفية العقارات وترتيبها، المحفوظات المحلية، روابط العقارات، وطلبات المعاينة أو الاستشارة.
- `/admin` لوحة الإدارة: المسودات والمعاينة الخاصة والنشر، إدارة التوفر والعقارات المميزة، متابعة الطلبات والمواعيد، تصدير النتائج، وتحرير محتوى الواجهة.
## إعداد الدخول عبر Google

1. في [Google Cloud Console](https://console.cloud.google.com/)، أنشئ **OAuth Client ID** من نوع **Web application**. إذا كان التطبيق في وضع **Testing**، أضف حساب الإدارة إلى **Test users** في Google Auth Platform.
2. أضف رابط العودة إلى **Authorized redirect URIs**. استخدم نطاق الإنتاج الفعلي والمسار `/api/admin/login/google/callback` دون شرطة أخيرة؛ مثل `https://example.com/api/admin/login/google/callback`. للتطوير المحلي يمكن تسجيل `http://localhost:3000/api/admin/login/google/callback` بدلًا منه، ثم فتح الموقع بعنوان `localhost` المطابق.
3. ضع نفس رابط العودة في `GOOGLE_OAUTH_REDIRECT_URI`، وأضف معرّف التطبيق وسرّه في `GOOGLE_OAUTH_CLIENT_ID` و`GOOGLE_OAUTH_CLIENT_SECRET`. اضبط `ADMIN_GOOGLE_EMAIL` على بريد حساب Gmail أو البريد الأساسي لحساب Google Workspace الذي سيُسمح له بالدخول.
4. احفظ الإعدادات لـ **Production** في Vercel وأعد النشر، أو ضعها في `.env` محليًا وأعد تشغيل الخادم. افتح `/admin` على النطاق نفسه واضغط **الدخول عبر Google**. رابط المعاينة على نطاق مختلف يحتاج رابط عودة وإعدادات منفصلة.

اللوحة والواجهات الإدارية تبقى محمية من الخادم. الموقع لا يطلب كلمة مرور Google ولا يخزّنها. عند الانتقال من النسخة السابقة، يمكن حذف `ADMIN_USERNAME` و`ADMIN_PASSWORD_HASH`؛ لن تعمل الجلسات السابقة، وتبقى العقارات والطلبات كما هي. لا تُفعّل اللوحة إذا كانت إعدادات OAuth ناقصة، ويظل موقع الزوار متاحًا طالما قاعدة البيانات متاحة.

## البيانات والنشر

- الموقع يحتاج إلى استضافة تدعم Node.js؛ استضافة الملفات الثابتة وحدها لا تشغّل خدمات العقارات والطلبات.
- شغّل بالخيار `NODE_ENV=production` خلف وكيل HTTPS يحافظ على ترويسة `Host`. يجب ضبط حساب Google المعتمد لتفعيل الدخول، ويصبح ملف تعريف ارتباط الإدارة `Secure` تلقائيًا.
- `DATABASE_PATH` يحدّد مسار قاعدة البيانات؛ المسار الافتراضي `data/almaktab.sqlite`. اربط المسار بوحدة تخزين دائمة واحتفظ بنسخ احتياطية آمنة باستخدام أدوات النسخ الاحتياطي لـ SQLite. هذه القاعدة تتضمّن بيانات تواصل العملاء؛ لا تجعلها متاحة عبر الويب أو Git.
- شغّل على قاعدة جديدة مع `SEED_DEMO=false` للبيانات الحقيقية. إيقاف البذر لا يحذف العقارات النموذجية الموجودة سابقًا؛ يمكن إلغاء نشرها من اللوحة. الصور النموذجية توضيحية ومولّدة وليست توثيقًا لعقارات معروضة للبيع.
- بيانات `localStorage` الخاصة بالنسخة السابقة لا تُرحّل تلقائيًا، لأنها محفوظة في متصفح كل مستخدم. أدخل أي سجلات مطلوبة في المنظومة الجديدة بعد مراجعتها.
- تحديد موعد في اللوحة يحفظه بتوقيت الإمارات. لا تُرسل إشعارات المعاينة إلى العميل تلقائيًا؛ يمكن التواصل معه باستخدام بيانات الطلب.
- لوحة الإدارة في هذا الإصدار تدعم حسابًا إداريًا واحدًا، وليس حسابات فريق متعددة. طلبات العملاء متاحة في لوحة الإدارة ويمكن تحديث قائمتها من داخل اللوحة.
- لا تستخدم أي بيانات اعتماد كانت مضمّنة في النسخة السابقة. ألغِ رمز بوت Telegram القديم أو دوّره من الجهة المسؤولة؛ حذفه من الشفرة الحالية لا يمحوه من سجل Git.
