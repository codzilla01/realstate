# النسخة التجريبية بدون قاعدة بيانات

المشروع يتضمن خادماً وهمياً كامل الميزات يعمل في الذاكرة، لتجربة المنتج
أمام العملاء أو تصوير العرض التقديمي دون تثبيت MySQL/Prisma.

```bash
npm run setup      # مرة واحدة
npm run demo       # يشغّل demo-api + واجهة Vite
```

| الرابط | الوصف |
|---|---|
| `http://localhost:5173/` | الموقع العام |
| `http://localhost:5173/admin/login` | لوحة التحكم |
| `http://localhost:4000/api/health` | فحص صحة الخادم الوهمي |

### حسابات الدخول

| الدور | الهاتف | كلمة المرور |
|---|---|---|
| مدير | `201000000001` | `admin1234` |
| وكيل | `201000000002` | `agent1234` |
| مشاهد | `201000000003` | `viewer1234` |

> الدخول بـ OTP في الوضع التجريبي يقبل الرمز `123456`.

## كيف يعمل

```
المتصفح ──► Vite :5173 ──(/api)──► demo/mock-api.mjs :4000
```
- `demo/mock-api.mjs`: خادم HTTP بلا اعتماديات، يحاكي كل مسارات الـ API
  الحقيقية (عقارات، عملاء، عقود، طلبات، مستخدمون، إشعارات، تقارير).
- كل التعديلات (إضافة عقار، تغيير حالة طلب…) تعمل فعلياً لكنها تُفقد عند
  إعادة تشغيل الخادم.
- **رفع الصور يعمل في الديمو**: تُحفظ الصور في الذاكرة وتُقدَّم عبر
  `/api/uploads/<id>` تماماً مثل النسخة الحقيقية.
- الواجهة تستخدم نفس الكود في الوضعين؛ لا فرق بين النسخة التجريبية والحقيقية.

## تطابق الديمو مع النسخة الكاملة

- نفس المسارات ونفس أشكال الاستجابات (بما فيها الأرقام الرقمية للمبالغ).
- نفس البيانات: 8 عقارات، 3 عملاء، 3 عقود، 3 طلبات، إشعاران، و3 مستخدمين —
  وهي نفس ما يزرعه `prisma/seed.js` في قاعدة البيانات الحقيقية.
- الفرق الوحيد: التخزين (ذاكرة مقابل MySQL) وبعض التحققات الصارمة في النسخة
  الحقيقية (Zod، بصمة الصور، حدود الباقات لاحقاً).

## استخدامه في البيع

- روابط معاينة فورية للعميل دون إعداد بيئة.
- تصوير فيديو/لقطات شاشة لصفحة البيع.
- استعراض الصلاحيات: سجّل بـ VIEWER ثم بـ ADMIN وأظهر الفرق.

## تحذير

`demo/` **ليست** نسخة إنتاج: لا مصادقة حقيقية، البيانات في الذاكرة، ولا حدود
طلبات. لا تنشرها على الإنترنت. احذف المجلد إن لم ترغب في تسليمه للمشتري
(لا يؤثر على بقية المشروع).
