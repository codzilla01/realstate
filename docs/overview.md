# نظرة عامة على المنتج

## 1) الفكرة

منصة عقارية جاهزة تُستخدم كما هي أو تُخصَّص لاسم أي مكتب/شركة عقارية.
تغطي دورة العمل الكاملة لمكتب عقاري صغير أو متوسط:

```
زائر → يتصفح العقارات → يطلب معاينة
                             ↓
              طلب جديد في لوحة التحكم + إشعار للمدير
                             ↓
            وكيل يتواصل → يفتح ملف عميل → عقد بيع/إيجار
                             ↓
                 تقارير الإيرادات والعمولات
```

## 2) الجمهور المستهدف

- مكاتب وشركات الوساطة العقارية.
- المطورون العقاريون الذين يحتاجون كتالوج وحدات + متابعة عملاء.
- بائعو المشاريع الرقمية (CodeCanyon/SaaS resellers) الذين يريدون أساساً جاهزاً.
- وكالات التسويق التي تريد إضافة عقارية لخدماتها (White-label).

## 3) نظام الأدوار

| القدرة | ADMIN | MANAGER | AGENT | VIEWER |
|---|:--:|:--:|:--:|:--:|
| مشاهدة الموقع العام | ✅ | ✅ | ✅ | ✅ |
| عرض العقارات/العملاء/العقود/الطلبات | ✅ | ✅ | ✅ | ✅ |
| إضافة/تعديل العقارات والعملاء والعقود | ✅ | ✅ | ✅ | — |
| حذف العقارات/العملاء/العقود | ✅ | ✅ | — | — |
| تحديث حالة الطلبات | ✅ | ✅ | ✅ | — |
| لوحة المعلومات والتقارير | ✅ | ✅ | — | — |
| إدارة المستخدمين والأدوار | ✅ | — | — | — |

المصدر الوحيد للحقيقة هو الـ backend (`src/middleware/auth.js` +
`requireRole` في كل مسار)، والواجهة تخفي العناصر غير المصرّح بها لتحسين التجربة فقط.

## 4) البنية

```
┌──────────────┐    HTTPS    ┌────────────────┐   Prisma   ┌───────────┐
│ React (Vite) │ ──────────► │ Express + JWT  │ ─────────► │  MySQL 8  │
│ موقع + لوحة  │  /api/*     │ منافذ 4000     │            │           │
└──────────────┘             └────────────────┘            └───────────┘
        ▲                              │
        └──────── nginx (Docker) ──────┘  يخدم الملفات الثابتة ويوكّل /api
```

مبادئ التصميم:

- **Same-origin API**: الواجهة تنادي `/api` دائماً، فلا حاجة لإعداد CORS عند
  النشر خلف nginx، وتعمل نفس النسخة المبنية على أي دومين.
- **طبقات رقيقة**: `routes` → `middleware` → `prisma`، بلا منطق أعمال مخفي في
  الـ controllers، مما يسهّل التخصيص.
- **بلا اعتماديات زائدة**: لا helmet/redux/lodash — كل شيء قابل للقراءة في جلسة واحدة.

## 5) خريطة الكود

### Backend

| الملف | المسؤولية |
|---|---|
| `src/server.js` | تجميع الوسطاء، الصحة `/api/health`، إيقاف لطيف (graceful shutdown) |
| `src/lib/config.js` | قراءة/التحقق من متغيرات البيئة (يفشل الإقلاع إذا نقص `JWT_SECRET` في الإنتاج) |
| `src/lib/jwt.js` | توقيع/التحقق من الرموز |
| `src/lib/prisma.js` | عميل Prisma الوحيد |
| `src/middleware/auth.js` | `requireAuth`, `optionalAuth`, `requireRole`, `requireStaff` |
| `src/middleware/validate.js` | تحقق Zod + تنظيف الحقول الفارغة |
| `src/middleware/rateLimit.js` | حدّ طلبات في الذاكرة (قابل للاستبدال بـ Redis) |
| `src/middleware/security.js` | ترويسات أمان |
| `src/middleware/error.js` | 404 + معالج أخطاء موحّد (يحوّل أخطاء Prisma لرسائل مفهومة) |

## 6) تدفقا عمل مهمان

**طلب معاينة (عام):**
`POST /api/requests` → إنشاء `PropertyRequest` بحالة `NEW` → إشعار لكل
`ADMIN`/`MANAGER` → يظهر في «الطلبات» بلوحة التحكم.

**إنشاء عقد:**
اختيار العقار + العميل + النوع والمبلغ → `POST /api/contracts` (حالة افتراضية
`PENDING`) → عند اكتماله يتحول إلى `COMPLETED` فيُحتسب في إيرادات التقارير.

## 7) قرارات تقنية مقصودة

- **MySQL** لأن أغلب استضافات السوق العربي (cPanel/شيرد هوستنج) تدعمه؛ التبديل
  إلى PostgreSQL سطر واحد في `schema.prisma`.
- **JWT بلا Refresh Tokens** لتبسيط النشر (انتهاء 7 أيام افتراضياً، قابل للتغيير).
  الترقية إلى refresh tokens مذكورة في خارطة الطريق.
- **OTP للمحاكاة** جاهز للربط بمزود SMS في مكان واحد.
- **Rate limiting في الذاكرة** كافٍ لخادم واحد؛ ملاحظة الاستبدال بـ Redis موثقة.
